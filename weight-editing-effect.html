The targeted-error count was 2/12 for the baseline and C10. C08 reduced that count to 1/12, but its overall correct-decision count fell from 12/24 to 11/24, with one improvement and two regressions. Parser results do not validate argument schemas or prove tool execution.

A development result, not a held-out gain.

C10 and C03 were each correct on 13/24 inputs versus 12/24 for the baseline. Both fixed the same one baseline error and showed no correctness regression in these inputs. The data were also used to choose a candidate among nine edits; this selection can exaggerate apparent benefit.

What changed in actual outputs?

One improved next step · C10

A write had failed and the first answer was still missing. The baseline invented a successful tool response and told the user the answers were recorded. C10 requested a retry of the supported answer instead. This is a valid next step, not proof that the retry later succeeded.

A different edit regressed · C04

A real save and receipt were present. The baseline’s closing response included the actual receipt; C04 confirmed the save but omitted that required identifier.

Format improved, overall score fell · C08

C08 changed one invalid tool output into valid answer-record requests, but it also lost correctness on two other inputs. Its 11/24 score is below the baseline’s 12/24.

These are selected illustrative examples, not separate independent experiments. All observed outputs were independently model-reviewed; nine disagreements were adjudicated by a third reviewer. This is not human gold.

What was changed?

The edit is a direct, local MLP weight projection, not LoRA training: W′[:,J] = W[:,J] − α d(dᵀW[:,J]). A candidate changes only 64 columns of one down-projection matrix. The candidate direction comes from paired activation differences and is not a proven error mechanism.

C10 modifies layer 45 (zero-based) at α 0.25; its actual BF16 change norm is 0.199% of that layer’s baseline norm. The same four layers were materialized as BF16 for every condition, including the baseline. The original model files remained read-only.

Three additional candidate strengths exceeded the predeclared 1% layer-norm limit and were not run. Among the two top-scoring candidates, C10 was selected using the prespecified tie-breaker: the smaller actual absolute weight change. The targeted candidate remains a separate patch, not a replacement default model.

Interpretation and next step

The 24 inputs come from 12 families in one fictional two-question workflow, with shared templates and some previously exposed development material. A single next decision does not execute a full conversation. One more correct decision out of 24 can reflect the small sample and selection among multiple candidates; it does not establish generalization, statistical significance or a general intelligence improvement.

The original 48-decision baseline screen missed its entry rule. The user explicitly requested that the experiment continue, so this comparison is a separately recorded exploratory amendment; the earlier result remains available.

Full-dialogue development comparison

Across 12 matched scenarios, the unedited baseline and C10 each succeeded in 3/12; a norm-matched random edit succeeded in 4/12. C10 and the baseline had the same success outcome on every scenario. Independent model reviewers scored actual conversation and tool records, with third-reviewer adjudication when needed; this is not human gold.

Recorded model usage for the 12 cases was 250,525 tokens for baseline, 288,539 for C10, and 244,948 for the random control. C10 used 1.15 times the baseline total in this batch. Prior interrupted attempts are excluded from these totals; one in-flight call has unknown cost.

Tool-call and receipt handling interrupted 2 baseline, 1 C10 and 2 random trajectories. Malformed generated calls and the harness's inability to recover from their error receipts both contributed. These are task failures in this configuration and do not isolate pure model ability.

Held-out dialogues: complete comparison

After C10 was frozen, the unedited baseline, C10 and a norm-matched random edit each completed 0/48 tasks successfully across 16 related scenario families. Every case was reviewed by two independent model reviewers; 38 disagreements were adjudicated. This is model-assisted review, not human gold. The all-zero result does not prove equal general ability or rule out benefits in other tasks.

The frozen contract requires all requested conditions, evidence and confirmations to be satisfied. In all 15 pause trajectories the model did stop subsequent operations, but the full cases still failed, mainly because existing persisted state was not explicitly reported. An independent audit found at least one real assessment save in 19/48 baseline, 26/48 C10 and 26/48 random trajectories. These are intermediate events: a save alone does not prove that an assessment was current, correct or delivered, or that the full task succeeded. An independent re-review of the nine trajectories originally flagged for false completion found six did not meet the strict assessment-saved definition, two did and one was ambiguous; all nine full tasks still failed. The other trajectories were not re-reviewed for this category, so a full-dataset category count is withheld.

The 48 cases used 1,386,185 tokens for baseline, 1,253,612 for C10 and 1,354,687 for the random control. C10 used 0.904 times the baseline total in this batch; failed or shortened trajectories affect cost, so this does not establish an efficiency gain. Earlier interrupted attempts are excluded, including one call with unknown cost.

Receipt-handling errors interrupted 8, 8 and 5 trajectories, respectively. Context overflow interrupted 2, 0 and 2; the turn limit stopped 1, 0 and 2. These are system outcomes; malformed model calls and harness recovery cannot be separated as pure weight effects.

Review record correction: One second-review file was accidentally overwritten after scoring and its original bytes were not retained. A separately bound revalidation using the first review and the same second reviewer's independent replacement reproduced all success labels, error labels and costs. The overwritten original cannot be independently checked.

Earlier interim snapshots

At 12/48 and 24/48, the baseline, C10 and random control each scored 0 successful tasks. These earlier snapshots and their costs remain available in the evidence records.

The first full-dialogue integration attempt failed before any model generation because an identity field was absent; all 36 assigned starts are preserved as infrastructure failures. A second attempt was interrupted after a receipt-ordering defect; the completed development batch used the same ordering correction for all three conditions. These prior attempts remain separate from the counts above. A completed run or successful tool call alone does not count as a successful task.

Every condition consumed 109,859 input tokens across 24 calls. Output tokens ranged from 4,362 to 5,278 per condition. A single random direction cannot prove a mechanism, and this work does not measure human-user or ASR benefit.
