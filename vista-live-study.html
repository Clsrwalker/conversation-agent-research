01 / MECHANISM & REFERENCE

What was missing from the interface?

VISTA motivates keeping original material accessible and using revisable working notes. We adapt that memory pattern to interview evidence; its visual-task results do not establish interviewing benefits. The source labels and participation contracts below are our adaptations, not claims made by the VISTA paper.

Original user turns→Observer evidence→Projector state→Actor + pending notes→Reply / explicit exit
01

Give each quote an explicit address

Why: v1 removed duplicate raw text but left turn IDs in a separate positional index. Luna cited u3 for the second user turn twice; both evidence patches were rejected and the reply was never delivered.

Change: put SOURCE turn_id=u2 next to that original body and restrict source IDs to delivered turns. The header is metadata, never part of the quote. Exact original text and quote validation stay intact.

Observed: the repaired trace commits the second-turn facts and the later correction, with no source-ID retry. All changes form a bundle; this is not an isolated causal estimate.

Reference: VISTA §3: originals and selective inspection; official tools implementation, pinned commit. Source framing is our interview-specific repair.

02

Separate eligibility from participation

Why: the old runtime gave the requested final explanation but returned complete after the participant explicitly asked to stop. In the boundary check, an optional invitation about repair still followed a refusal.

Change: omit ineligible completion from the offered actions; define explicit user exit as withdraw, even when all fields are satisfied. When the Projector already reports a refused field, remind the Actor to acknowledge without inviting more information about that field. A short response may keep the interview open.

Observed: the final response uses withdraw; in the two-turn check, refusal first leaves the session active, then explicit exit withdraws it. The model still selects the message and next conversational move.

Reference: invalid-action masking is a conceptual analogy, not direct LLM evidence. Participation semantics follow this project's interview contract.

03

Keep a pending request separate from facts

Why: a completed answer checklist can coexist with an explanation the user asked to save for later.

Change: bounded, revisable notes accompany the Actor's final response. They do not write evidence or authorize completion, and need no additional reflection call.

Observed: Luna kept the impact explanation pending across three responses, then explained it and cleared the notes on the fourth. The old runtime also respected that timing: no isolated note benefit is claimed. No history or evidence-inspection tool was called in these successful traces.

Reference: VISTA §3.2 working memory. Revision inspection remains supported by the earlier scripted engineering checks; its autonomous benefit is unmeasured here.

04

Count the entire interaction

Why: shorter raw context can be offset by more instructions, schemas, notes or retries.

Change: the explicit Luna entry shares one budget and durable ledger across Observer, Actor and reads. It reserves request and output capacity, logs provider usage and stops on uncertain outcomes without automatic API retry.

Observed: both complete four-turn runs used eight calls. V2 used 24,922 total tokens versus 23,263 before the additions. The incomplete v1 run cannot be treated as a cheaper successful interview.

Reference: OpenAI Structured Outputs for the schema adapter. Full-request accounting and its spending limits are project engineering controls.
