WHERE THE PROJECT STANDS

The loop runs. Reliable assistance is still the research problem.

Implemented

Controlled, inspectable runs

  • Timestamped conversation replay and delayed search/read jobs.
  • Agent-selected tool use and publish, update or withdraw actions.
  • New-event checks before publication; checkpoints and durable run records.
Known limitations

Evidence does not guarantee help

  • An answer can rely on incomplete excerpts.
  • Searches can repeat until the budget runs out.
  • Evidence can arrive without an answer reaching a card.
Not integrated / untested

Beyond the replay prototype

  • No live microphone or real-ASR evaluation.
  • Web retrieval is available in question tests; no deployed live-assistance interface.
  • No demonstrated benefit in a human user study.

EXPERIMENT 01

Tool feedback & recovery

Measured · exploratory
Problem

A model can mistake a document title for its source ID, then stop or wait for a job that never started.

What changed

Search results identify excerpts and truncation. Read failures state that no job started, list already available sources and actual pending searches, and suggest a possible next action.

An optional recovery prompt can offer one further opportunity per conversation revision if the model ends its turn after a recoverable retrieval failure with no pending work. The agent can still wait or stop.

What was compared

All three configurations received the same improved tool feedback. agent-led and agent-led-recovery differ only in the additional recovery switch. The native reference uses the same environment and model.

Three configurations × six exposed development scenarios × one run = 18 runs. Reviewers received anonymous output packets.

MAIN FINDING

The recovery prompt was never triggered.

All 18 runs recorded zero recovery prompts. The mechanism passed scripted tests, but this batch cannot show that it improves answer quality or reduces cost.

01 / THE INTERVENTION

Could visible progress improve the next decision?

The earlier baseline could answer from an excerpt or keep searching without delivering help. We added a short factual record of queries, arrived evidence, pending work and displayed cards before each model request. The agent still chose its next action.

02 / THE RESULT

The primary outcome stayed at 5 / 14.

“Useful help” means a supported, correct active answer at the scenario deadline, without a material extra error. Seven scenarios required help; two repetitions gave 14 help opportunities per configuration. The other six runs tested appropriate silence.

Tokens fell from 745,280 to 620,471 (−16.7%). Help runs ending without an active card rose from 6 to 8. Material-error runs fell from 3 to 1, and silence passed 6/6 in both arms. These changes did not produce a net gain in useful help.

03 / A DELIVERY FAILURE

The guide arrived. The answer never reached the conversation.

In the RillStat case, a participant asked whether a report marked “no notable difference” justified calling two processes interchangeable. The conversation clarified that only an ordinary difference test had been run, with no equivalence margin or equivalence analysis.

Failure to reject the difference-test null does not establish equivalence. The badge alone cannot support the interchangeability claim.

04 / LIMITS & NEXT STEP

Test the handoff from evidence to delivery.

The next research question is whether an explicit delivery decision helps when evidence has arrived but the conversation still has no answer. That comparison is planned, not implemented or measured. The progress-message configuration remains experimental.

The current evidence comes from one local model, ten fictional scenarios and a diagnostic lexical retriever. Two arm-anonymous AI reviewers agreed on all 40 sets of labels, but two baseline grading boundaries remain uncertain: sensitivity analysis places baseline useful help at 4–6/14, against 5/14 with progress. There are no human ratings or live-conversation results.

Protocol, scoring and interpretation details

Control: agent-led-recovery; treatment: agent-led-progress. Local Qwen2.5 14B Instruct; temperature 0; context 16,384; up to 24 calls, 120,000 soft tokens and 1,200 output tokens per call. Runs were serial, with paired arm order reversed across repetitions.

The progress record only uses delivered messages, not future conversation or unread documents. Its cost counts toward the shared token budget. It is capped at six recent rows per category and 6,000 characters, with omissions marked; the observed maximum was 2,110 characters. It appeared in all 143 treatment requests and no control requests.

Help is evaluated from the active card at the fixed deadline. Private prose does not count as delivered help. Silence controls require no unnecessary card during the window. Transient material errors are counted separately from final success.

Six exposed diagnostic runs and four development runs are excluded. The held-out scenarios were independently authored around known failure families, not drawn from an external benchmark. This comparison tests the complete progress message, not each field separately.

Exact repeated queries fell from 4 to 0, and full-document arrivals from 45 to 26. No summary-model call occurred. These are trace observations, not separate evidence of improved assistance.

No live web retrieval, microphone, real ASR, long-term memory or user study was tested.

Engineering validation for the intervention

64 selected tests, 4 additional summary-identification checks, 23 retrieval checks, 24 dataset hashes and 36 original baseline files were verified. These check software behavior and record integrity; they do not establish assistance quality. Context-compaction ordering used a substitute summarizer, not a real long conversation.

EXPERIMENT 03

Conversation state from ASR

Proposed · no real-ASR results

Speech recognition can rewrite a sentence while an investigation is running. A person can also change what they want. The harness needs to handle both without treating every new fragment as a new task.

Problem

The current prototype passes partial and final transcript events to the model. It does not maintain a separately consolidated latest transcript for each speech segment.

ILLUSTRATIVE INPUT · NOT A MEASURED RUN
Partial

“The file is 12 MB.”

segment 1
Final

“The file is 120 MB.”

segment 1

An ASR correction replaces a recognition hypothesis. A later human change of plan is a separate utterance. Both can affect an answer.

Candidate change

Maintain the latest text for each segment alongside its revision history. Present the current conversation and the changes to the agent, so it can judge whether an investigation is affected.

Separate small transcript refinements from changes that alter the question. The decision to investigate remains with the agent.

What is known today

Synthetic events can arrive during investigation, and card publication checks for unread events. Earlier experiments included authored ASR-like corrections.

No real microphone or ASR stream has been evaluated. Current replay timing is simulated; it does not measure live response latency. The diagnostic retriever also needs replacement before testing multilingual real-world retrieval.

Proposed paired evaluation

Corrected transcript

Can the agent understand correctly transcribed speech?

Recognition output delivered at its recorded arrival times.

What is lost through transcription under matched timing?

Measure help, errors and unnecessary action.

Compare useful help, false interventions, mistaken task revisions, outdated cards, repeated work, cost and actual elapsed response time. Log transcript arrival times so recognition delay can be separated from investigation delay.

First characterize the frozen baseline. Then compare an input-state change under the same conditions. Collection, ASR integration and this study have not yet been completed.
