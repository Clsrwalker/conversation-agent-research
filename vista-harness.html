Adapt mechanisms, keep the research question

VISTA supplies the inspiration: retain originals, let the agent inspect selected material, and maintain revisable working notes. Its interactive visual tasks do not establish an interviewing benefit. Raw history, read-only access and evidence projection already existed in our 6 November Harness.

AdditionMethodAuthority boundary
Evidence inspectionUp to four labeled views by requirement/revision or user-turn span, with original question context and revision links.Read-only. Partial and omitted views are explicit; the tool does not decide what the evidence means.
Session working notesThe Actor may replace up to six notes with prior-turn references. Changes to associated evidence produce review flags.Non-authoritative. Notes do not commit facts, choose the next question or authorize completion.

The normal loop is user archive → Observer evidence → Projector state → Actor reading view → optional inspection → Actor response. Notes can accompany that final response; there is no additional planner or mandatory reflection call. Reading requests share the existing allowance of two per user turn.

What happens at a correction

Authored demonstration, with scripted Observer and Actor outputs. The following sequence comes from the saved acceptance trace, not an LLM run.

01

Archive the first disclosure

The authored user says a device failed, a restart helped, and asks for a warranty explanation. The scripted Observer records failure and recovery; the Actor stores a pending-request note.

02

Receive a correction

The next user turn says the failed device belonged to a colleague and the participant’s own device never failed. The Observer commits a new failure revision.

03

Project consequences

The old recovery record is invalidated by the changed prerequisite. The previous failure is superseded; the pending note is marked as needing evidence review.

04

Choose a labeled inspection

The scripted Actor requests the recovery evidence and its dependencies. The Harness returns the old bound failure, the new failure revision and original source context without modifying evidence.

05

Keep the current request visible

The Actor receives the inspection alongside recent role messages and the non-authoritative note. It returns an authored response addressing the explanation request and clears that note.

06

Restore the same state

Saving and replaying produce identical evidence, note state and next input. Completion eligibility remains a Projector result; it does not force the Actor to end the interview.

A second trace: long history, partial reading and recovery

An old user turn asks to defer a topic and contains more than 13,000 characters. After four exchanges, the scripted Actor selects the whole old turn. The 12,000-character read limit returns an explicit omission. The process is deliberately interrupted at that point.

Replay reconstructs the exact next Actor input, preserves the used read allowance and reuses the completed Observer result. The scripted Actor then requests characters 0–120, receives their exact text with the original length and a next offset, and answers. The full original remains archived. No summary or external model reconstructs the omitted text.

Limits that remain

  • No LLM behavior comparison, user study, human preference calibration or training was performed. Authored responses do not demonstrate autonomous inspection or useful notes.
  • The planner uses actual local HF tokenization of a reviewed renderer branch plus explicit reserves. Native Ollama token equivalence and truncation behavior have not been measured.
  • The Observer retains full history and can reach an explicit capacity failure. No automatic summary or semantic retriever is added; reserved template-token strings are rejected.
  • Provenance validates exact sources, not semantic truth. Offline tests of instruction-like notes establish software authority boundaries, not model prompt-injection resistance.
  • The release pins an existing Windows tokenizer runtime, not a standalone cross-platform image. Future live use must pass model and server preflight.
  • Data-to-Harness input reconstruction is a subsequent task. Missing human tool calls, historical Evidence State and working notes are not fabricated.
