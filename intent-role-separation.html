23 OCT 2026 · EXECUTED SYNTHETIC REPLAY

One model, separate intentions and work

Separate chat and work roles delivered complete, correct final answers in 14/16 trajectories; adding an independent intention tracker did so in 12/16, the same count as the unified actor. All 48 runs finished. This small pilot does not establish a tracker benefit.

What changed

The same Qwen2.5 14B Q4_K_M model performs each role. Work retrieves and reads; chat publishes or withdraws visible answers. The independent tracker proposes versioned intention changes from arrived raw conversation. Its durable ledger keeps requests and execution receipts separate. No LoRA is trained or loaded.

All three conditions use the new experimental stepping session and the existing causal document/card tools. The unified actor can use both tool sets. Split roles alternate work and chat. The tracker condition adds state updates to the same total budget: six calls per stage, three stages. Token usage and remaining actor calls can differ. This is not a direct comparison against the native DeepAgents baseline, and the Lab default is unchanged.

Families complete in both repeats: Unified actor 5/8; Chat + work 7/8; Tracker + chat + work 6/8. Omission means missing content; an answered but factually wrong choice is scored separately.

  • The tracker did not reduce omissions relative to the split roles. Omissions affected 3/16 unified runs, 2/16 split runs and 2/16 tracked runs. All six workshop runs missed the explicitly requested $23 price. The two tracked room runs kept the old, more expensive choice after Wi-Fi was removed.
  • Valid state and delivered help diverged. In one tracked room run, work privately identified the correct cheaper room, but that prose was not saved to shared notes and chat repeated the old answer. Conversely, both multiple-owner tracked runs ultimately answered correctly despite invalid intermediate patches and inconsistent tracker lifecycle state. These are diagnostic observations, not isolated causal effects.
  • No-change handling and late evidence remain limited tests. The secondary review records redundant updates that changed provenance without changing the request; those are not automatically false user-intent changes. All six seeded old desktop reads were cancelled before arrival. The study therefore does not test consumption of an actually late obsolete result.

Comparison conditions

The cases cover local replacement with retained constraints, withdrawal, reopening, no-change dialogue, an unaccepted assistant proposal, combined changes, multiple request owners, and an inherited pending obsolete read. Every condition receives the same arrived original dialogue and source environment. Gold annotations stay outside model requests.

The pending-read case starts with a shared, actually executed search/read setup. All six runs cancelled the old read before arrival, so handling an actually arrived obsolete result remains untested. This is a controlled initial condition, not actor-selected work. Development runs are archived separately from the evaluation batch. Final-card scores do not summarize every intermediate card a user would have seen.

Three desired recovery/handoff properties fail. Atomic rollback, valid transitions, explicit notes, budget accounting and stale-input rejection work. The tracker and handoff diagnostic commands retain exit code 1 for those missing capabilities. Successful guard assertions do not mean the faulty answers pass a quality test.

The intended architecture remains one model in three functional roles: an independent intention tracker maintains requests and changes; work produces evidence and results; chat handles clarification and delivery. Next candidates are precise rejection feedback with bounded retries, a concise work-result artifact tied to the intent version, and separate computed/delivered state. These changes are proposed, with no repair benefit measured.

Diagnostic limits and supporting records

The ten failures comprise six workshop, two room, one answer-scope and one arrival-window case. Full inputs do not identify why a model omitted a fact. Explicit handoff success with a scripted model does not establish real-model benefit. Early workshop gold over-specifies price; this diagnosis uses the final explicit request. No LoRA, ASR, new user study or consumption of an actually arrived obsolete read was tested.

24 OCT 2026 · PLANNED STUDY + DATA CONTRACT CHECKS

A trained LoRA for the intention tracker

The next direction shares one base model and gives each job its own trained adapter. The first experiment trains only the tracker LoRA; work and chat stay identical across both arms. The earlier experiment above used no LoRA. No adapter has been trained and no omission reduction has been measured.

Train state updates, including what must stay

Input: original arrived dialogue, current intentions and supporting event IDs. Target: additions, local revisions, withdrawals, reopening or no change. “Free, desktop and offline” followed by “switch to mobile” must retain free and offline while replacing desktop. Metadata and expected post-state stay outside the training input.

Created now: 24 illustrative examples, 12 Chinese and 12 English, in 12 paired families. They cover changes, unchanged constraints, unaccepted suggestions, quoted requests, ownership and recovery. All are exposed development material. Two uncertain-owner examples still need an agreed annotation convention and human adjudication.

Planned collection: 800 training / 200 development / 400 test updates. These are future targets across 200 / 50 / 100 scenario families, with four decisions per family. Keep dialogue prefixes, translations, paraphrases and counterfactual siblings in one split. A quarter of the proposed training rows are no-change, proposal or quotation negatives. The old eight-family pilot remains a regression set.

Completed checks, training readiness and records

The actual offline check replayed 24 examples and verified 24 isolated SFT pairs, 22 target operations, six no-change cases and 40 untouched records. Three corruptions were rejected atomically. A fourth omitted a requirement: the runtime accepted it, and only the authored expected-state check caught it. This distinguishes schema validity from semantic correctness.

Review found a shortcut in the first version: historical patch IDs exposed scenario labels. Neutral runtime IDs replace them, and the second check passed. The original attempt is retained. Independent model review is separate from still-pending human validation; these examples are not automatically approved for training.

The current inference artifact is Qwen2.5 14B GGUF Q4_K_M. The candidate training path uses a pinned compatible Hugging Face checkpoint with PEFT/QLoRA; both comparison arms must use the same new stack. A 16 GB RTX 4080 SUPER is available, but memory fit, package compatibility, token masks and adapter save/reload have not been tested. Full data collection, training and model evaluation remain unfinished.

Limits and next work

  • Eight authored synthetic families, not independent real users.
  • Two repeats per family are correlated; report both and family-level outcomes.
  • All arms use the new stepping session, not the native DeepAgents baseline.
  • Role restriction, alternation and additional state/context are part of the treatment.
  • Equal call ceilings do not equalize input tokens or available actor calls.
  • Final-card scoring is the primary endpoint; intermediate user exposure may differ.
  • No LoRA, ASR, live Lab integration or production benefit established.

Keep the independent tracker as an experimental component. The next version should test explicit work-to-chat handoff and a bounded tracker recovery path with precise validation feedback and raw-conversation fallback. Preserve atomic state checks, current-input cursors and shared budgets. Compare on fresh variants plus exposed regressions before considering LoRA or changing the Lab default. These repairs have not yet been implemented or evaluated.
