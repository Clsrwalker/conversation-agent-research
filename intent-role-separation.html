23 OCT 2026 · EXECUTED SYNTHETIC REPLAY

One model, separate intentions and work

Separate chat and work roles delivered complete, correct final answers in 14/16 trajectories; adding an independent intention tracker did so in 12/16, the same count as the unified actor. All 48 runs finished. This small pilot does not establish a tracker benefit.

What changed

The same Qwen2.5 14B Q4_K_M model performs each role. Work retrieves and reads; chat publishes or withdraws visible answers. The independent tracker proposes versioned intention changes from arrived raw conversation. Its durable ledger keeps requests and execution receipts separate. No LoRA is trained or loaded.

All three conditions use the new experimental stepping session and the existing causal document/card tools. The unified actor can use both tool sets. Split roles alternate work and chat. The tracker condition adds state updates to the same total budget: six calls per stage, three stages. Token usage and remaining actor calls can differ. This is not a direct comparison against the native DeepAgents baseline, and the Lab default is unchanged.

  • The tracker did not reduce omissions relative to the split roles. Omissions affected 3/16 unified runs, 2/16 split runs and 2/16 tracked runs. All six workshop runs missed the explicitly requested $23 price. The two tracked room runs kept the old, more expensive choice after Wi-Fi was removed.
  • Valid state and delivered help diverged. In one tracked room run, work privately identified the correct cheaper room, but that prose was not saved to shared notes and chat repeated the old answer. Conversely, both multiple-owner tracked runs ultimately answered correctly despite invalid intermediate patches and inconsistent tracker lifecycle state. These are diagnostic observations, not isolated causal effects.
  • No-change handling and late evidence remain limited tests. The secondary review records redundant updates that changed provenance without changing the request; those are not automatically false user-intent changes. All six seeded old desktop reads were cancelled before arrival. The study therefore does not test consumption of an actually late obsolete result.

The cases cover local replacement with retained constraints, withdrawal, reopening, no-change dialogue, an unaccepted assistant proposal, combined changes, multiple request owners, and an inherited pending obsolete read. Three desired recovery/handoff properties fail. Atomic rollback, valid transitions, explicit notes, budget accounting and stale-input rejection work. The intended architecture remains one model in three functional roles: an independent intention tracker maintains requests and changes; work produces evidence and results; chat handles clarification and delivery. Next candidates are precise rejection feedback with bounded retries, a concise work-result artifact tied to the intent version, and separate computed/delivered state. 2026年10月27日 · 原因诊断 · 复用已暴露输入

Tracker 为什么失败：接口错配已确认，原岗位修复也不稳定

当前不应换底座或直接加训练。核查改用了没有训练过的接口；回到原生接口后，6 条原训练样本也只修复 2 条。数据覆盖存在明确偏斜，但尚不能把失败唯一归因于数据或训练步数。

要查清的问题：区分核查方法、训练数据、训练实现和推理配置的影响，解释归属、错误撤销恢复和不确定状态为什么仍会错。

本记录共新增 18 次生成：适配器关闭对照 12 次，原训练样本复现 6 次；新增训练 0 次。两项检查回答不同问题，分别计分。诊断已完成表示检查与记录完成，不表示质量验收通过。

已证实的问题

  • 核查任务与训练契约不一致 500 条训练 completion 全部使用 operations，零条 checks/verdict；新核查同时改变系统指令、输入状态投影和嵌套输出。相同核查输入，历史 v2 可执行报告 0/12，关闭适配器后 10/12；合法 JSON 为 1/12 对 11/12。

    把当前 LoRA 直接用于这个新核查岗位是未验证的方法变更；不能把全部失败先归咎于标签质量。现有证据支持新任务上存在适配器相关的不兼容。

    结论边界：没有分别操纵输入投影、指令与输出格式，不能确认哪一项占主导，也不能证明关闭 LoRA 就能解决意图遗漏。

  • 问题不止是新 JSON 格式 同一 v2 在 6 条精确原训练 prompt 上，operations 6/6 可执行，但完整焦点修复只有 2/6：归属 0/2，撤销恢复 1/2，不确定状态 1/2。三条漏修，一条错误撤销。

    当前 checkpoint 连这些已经训练过的修复例也没有稳定复现，不能把训练完成或 loss 下降当作岗位能力验收。

    结论边界：只有 6 条定向训练样本；没有在相同六条上关闭适配器，不能断言这些语义错误由 LoRA 单独造成，亦不能推断全量欠拟合。

  • 修复数据的身份与位置覆盖偏窄 30 条注入归属修复全部针对 i2、引用 seq0、修回首位说话人；原测试 20 条归属故障中 19 条在 i3。8 条训练误撤销修复全部是第二人的 i4，原测试 5 条全部是第一人的 i1。140 条故障训练没有同原文干净前态配对；140/140 修复放目标末尾，其中 111 条之前还有当前操作。

    训练设计给了身份、位置和动作顺序捷径，缺少同内容不同状态的反例。后续数据修订应优先修这些结构，而非无差别扩大数量。

    结论边界：这些是已确认的数据分布事实，不是模型采用捷径的因果证明。另有 4 个普通归属更新操作，以及 4 条普通样本中的 5 个 reopen 操作，不能将固定模式泛化到所有训练操作。尾位置也解释不了六条中的空输出与错误撤销。

  • 核查功能的范围不能覆盖所有遗漏 当前核查只修改已有记录的 owner/status；上一轮一条正确前态经普通跟踪后 i4 文本损坏且漏掉新 i5，元数据核查无法修复。

    对这版功能只能宣称核查已有意图的归属和状态，不能宣称已实现完整意图恢复。

    结论边界：本轮不新增文本恢复或缺失记录恢复，以遵守限定范围。

已检查、当前不支持的解释

  • 未发现可解释全部失败的训练实现错误 500/500 tokenizer 前缀与目标对齐；500 行各处理一次，32 次 optimizer 更新与最后 4 行累积组吻合；672 个适配器张量有限、336 个 B 矩阵非零，梯度有限且非零；CPU loss/梯度对照通过。加载工件和已记录量化设置匹配。

    没有证据支持“根本没训练、标签整体错位、加载了空适配器”等解释。

    结论边界：检查通过不证明优化配方足够，也不排除量化损失或未测实现因素；没有重放完整 CUDA 训练。

  • 当前不支持大面积错误标签作为主因 750 条 train/dev/test 结构与输入目标对应通过，定向复核 20 条未发现焦点语义错标；发现一处冗余 assistant 引用。

    目前更明确的问题是覆盖与任务契约，而非已有证据证明大量标签错误。

    结论边界：结构检查不是语义标注检查；20 条是未盲人工智能定向复核，并未逐条人工核验全部 750 条。

  • 新诊断没有输出长度截断 18 条新增生成全部以配置 EOS 151645 结束，均未触发 token 上限；历史 24 条输出也未触顶，但没有保存终止 token。

    不能用“输出上限太小”解释这些新增样本的遗漏。

    结论边界：历史精确终止原因不可追溯；正常 EOS 不表示答案完整。

仍未确定的原因

  • 训练预算与目标权重的作用尚未识别 当前只训练 1 epoch、32 次更新；按样本平均 completion loss，长度 6–148 token，同组最短样本单 token 相对权重可为最长约 24.67 倍。

    训练强度、短输出权重和岗位监督都是候选解释，但不能据此直接加 epoch 或调 rank。

    结论边界：没有固定其他因素的训练干预；欠拟合、过拟合、学习率、rank、量化各自影响未确定。

  • 数据偏斜究竟造成多少失败尚未识别 已确认身份/位置集中和缺少干净配对，但原训练样本也只修复 2/6。

    仅用“未见位置泛化差”不能解释全部现象；可能同时存在监督目标与学习不足。

    结论边界：没有重训平衡数据版本，不提供各原因的百分比分摊或成功率预测。

失败与限制

  • 适配器关闭的 12 次生成全部完成，但整个 collection 的最终状态仍为 failed：退出 PEFT disable_adapter 上下文后，0 trainable 参数断言失败。原始失败记录保留，没有将其改写为成功。
  • 源码与 tiny CPU 重现表明重新启用 adapter 会改变 requires_grad 标志；不改变参数值或 eval 状态。每次实际生成前均记录 336 层 disabled、0 trainable，后验复核确认 12 条输入、日志、输出完整；原进程退出后的逐参数标志不可重建。
  • 关闭适配器只修复 2/6 故障，均属不确定状态；其中中文修复引用缺少指代所需的 assistant 原文，充分证据支持的修复仅 1/6。归属和撤销恢复仍未修复。
  • 原生六条训练复现中，一条将应为 uncertain 的要求错误 withdraw；合法 operations 不能成为自动提交的充分依据。
  • 训练审计首版根目录错误、CPU 上下文复现首版 CUDA 初始化检查失败均保留；修正的是新诊断工具，未改历史训练与输出。
  • 保持原底座与适配器工件不变；关闭适配器仅用于定位，不是更换生产岗位或替代同底座多 LoRA 方向。
  • 只使用已暴露核查输入和已训练样本，无新场景、无新训练；不能据此声称最终任务质量、用户收益或未见组合泛化改善。
  • 对照严格绑定消息、token IDs、工件和配置，但历史/新增运行不在同一进程；没有独立硬件层记录保证逐位确定性。
  • 核查未造成误改的历史结果以零次提交为前提，不能解释为核查准确。
  • 部分根因仍是候选解释。记录完成不代表原因已全部因果识别，当前功能仍不具备启用依据。

下一步（计划，尚未执行）：保持当前底座与 LoRA 冻结，暂不启用失败的核查。优先把核查职责限制在原生 operations 契约并保留 harness 的来源、归属和状态转换校验；是否有效仍需在原小样本验收中验证。本轮到此停止新增生成。平衡身份/位置、补干净配对和修复顺序的数据方案只作修订依据，尚未训练。

  • Two repeats per family are correlated; report both and family-level outcomes.
  • All arms use the new stepping session, not the native DeepAgents baseline.
  • Role restriction, alternation and additional state/context are part of the treatment.
  • Equal call ceilings do not equalize input tokens or available actor calls.
  • Final-card scoring is the primary endpoint; intermediate user exposure may differ.
