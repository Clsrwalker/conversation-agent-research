# 从真实任务出发研究 conversation harness

日期：2026-10-17（America/Halifax）  
状态：**实验设计 v0.1；尚未运行。本文没有新增模型实验或效果数字。**

## 1. 要回答的研究问题

在持续、有业务目的的对话中，用户会一次提出多个要求、补充隐含条件、临时离题、改口或停止。固定模型、资料、工具和资源上限后，harness 能否保持当前有效的目标，采取正确行动，并只在有实际证据时声称完成？哪些失败可由简单提示改善，哪些需要持久状态或完成核验？改善能否迁移到没有用于调参的新问卷？

教授的汽车培训案例是研究动机。企业尝试过哪些产品及其失败原因，目前没有可审计记录，不能当作模型比较结果。研究贡献应是“诊断出一种可复现的失败，并验证针对它的改变在什么条件下有效”，而不是增加一个 function、状态表或 JSON 读取接口。

汽车员工培训与电信优惠办理作为两个开发领域；只有未参与调参的新问卷/第三领域用于迁移检查。心理健康只作为未来可能的应用方向，本轮不开展临床任务，也不推断疗效。对话结束可以是完成、需要补训、等待信息、明确暂停或用户退出；不以强迫问完所有题为成功。

## 2. 现有 harness 能发现什么

| 失败 | 操作化定义 | 现有证据/能力 | 本研究需要补的部分 |
|---|---|---|---|
| H1 漏识别/漏澄清 | 对已揭示要求的理解错误，或必要歧义未澄清；单纯漏办先作行为标签 | 现有独立前缀识别 probe 与多需求回放可发现遗漏；probe 不等于运行时真实认知 | 分开记录已表达识别、错误识别、未观察到识别证据；无证据保留 unknown，不能把识别后未执行算成不理解 |
| H2 跨轮丢失/状态过期 | 先前正确记录或交付的仍有效要求随后丢失，或已更正内容仍被使用 | Aster 的卡片更新曾删除独立答案，之后修复；只看最终评分会漏掉过程损失 | 逐轮字段版本、依赖失效、改口后状态、对话恢复；区分输出维护失败和不可观测的“内部遗忘” |
| H3 错误执行 | 动作、参数、结果解释或必要先后条件错误 | 有工具错误日志，但现有会议任务没有充分的业务动作及依赖金标 | 授权、资格、答题记录、评估保存等可核验动作；允许多条正确路径 |
| H4 虚报完成 | 完成声明超出了当时业务状态/交付凭据支持的范围 | Aster 有收到编辑失败后仍认为卡片已完整的记录；不是整个运行提前结束 | 同时比较声明、工具确认、最终业务记录和用户可见回执 |

现有主环境是**旁听会议并发布知识卡片**。单问答适配器也会在交付一次回答后结束。它们不能直接充当持续的培训考核或套餐办理环境。现有 SQLite 账本、checkpoint、工具/model 调用记录与事件队列可以复用；原冻结 baseline 保留，新环境中的适配版必须另取版本名，不能沿用原成绩。

本地审计依据：`experiments/deep_conversation/agent.py`、`lab.py`、`direct_request.py`、`world.py`、`experiments/conversation_harness/runner.py`；既有研究记录位于 `output/research/2026-10-17/budget-state-repair/TRACE-ASTER.md`、`model-harness-factorial/RESULTS.md`。这是已有代码和日志的解释，不是新的效果实验。

## 3. 两个场景及可核验终态

### A. 汽车员工培训：首个主场景

将辅导与考核作为同一会话中的两个明确模式。员工可问资料内的问题；进入考核后，bot 提出情境题、接收选择与解释、处理一个回答覆盖多个字段、追问缺失理由，并保存有证据的评估。

建议首批三个任务家族：诊断步骤的解释、维修授权/客户沟通、培训记录的修订。具体维修知识须来自适用车型的授权资料并经专家核对；未取得新车型资料前，只能称为一般汽车培训原型。

示例为**虚构任务蓝图，不是维修操作指导**：员工回答情境题 Q1，同时解释判断依据；接着询问术语；bot 解答后应恢复仍未完成的考核；员工纠正 Q1 理由；保存工具首次失败。正确结果是最新答案、来源轮次、是否接受过辅导、对应 rubric 与保存状态一致。保存失败时可以说“评估已形成，尚未保存”，不能说已归档。

三个对象必须分开：bot 给出的解释是否正确；员工是否独立答对；评估记录是否准确保存。刚教过答案再让员工复述，应标为 assisted，不能算独立掌握。文本解释的评分也不等于技师实际动手能力或正式认证。

### B. 电信优惠办理：第二领域

虚构固定资费表和优惠政策。用户要求便宜套餐，同时说自己是老客户；bot 应确认必要资格，比较标准方案及适用优惠，披露影响选择的条件，在用户接受后提交模拟变更并报告实际状态。

首批三个任务家族：标准价格加隐含优惠资格、需求/资格更正、已接受方案的执行与失败恢复。事件状态至少区分 `offer_created`、`accepted`、`change_pending`、`change_applied`、`confirmation_delivered`。模拟数据库应用变更与生成回执不能由 LLM 文字宣称替代。

不连接真实运营商账户、真实付款或邮件。模拟邮件投递确认只证明沙箱内状态，不能外推真实系统的送达或 exactly-once 保证。现实法规只作未来业务设计参考，首轮的确定性规则以冻结的虚构合同为准。

## 4. 人类来源与金标如何建立

| 来源 | 用途 | 不可声称的内容 |
|---|---|---|
| Taskmaster-1 汽车维修预约的双人 WoZ 子集 [S1] | 人类表达、补充、询问和改口的素材；保留原 conversation ID、轮次与署名 | 是角色扮演对话，不是自然发生的公司客户通话，也不是技师知识考核 |
| ASE 2026 技师/服务顾问指南 [S2–S3] | 专家定义的任务范围、知识点与考核形式 | 服务顾问标准不能替代机械实操；公开样题不等于允许整份再发布 |
| AURACA101 标准和考核要求 [S4] | 需求澄清、未满足要求、跟进与完成证据的 rubric 来源 | 不是现成逐轮对话金标；标准要求的客户数不是本研究样本量依据 |
| 合作方授权资料和专家另写情境 | 新车型专用知识、容许答案、关键错误及辅导标记 | 未获得之前不能声称已建立企业真实场景 benchmark |

Taskmaster 全库混有双人 WoZ 和单人自写两种来源，应筛选双人汽车子集后再报告实际数量，不套用全库数量。保留原始人类文本的任务标为 human-source；研究者改写、模型补句及新增约束分别标注。公开数据的署名/许可随来源记录；只链接 ASE 原文，不批量发布其样题。AUR 的再分发许可尚未核实。

每个 case 保存 source ID/version、改写记录、用户可知事实、允许披露规则、关键需求、可接受结局、评分依据及审核人。原固定对话用于离线理解诊断；一旦 agent 自由追问，后续用户回复必须来自新的人类或明确标注的模拟器，不能机械重放原下一句并声称交互真实。

运行前请两位评审独立检查案例与金标，其中至少一位具备相关领域经验；记录分歧及裁决，未经专家检查的汽车评分只标 provisional。后续小规模真人锚点可检查模拟器是否过度合作，但不据此宣称真实用户收益。

## 5. 最小实验设施

```text
任务包：公开规则/资料/问卷 ──────→ 各实验组共享的 actor 接口
                                           ↕ 对话和工具
用户模拟器：私有 profile + 披露策略 ↔ 确定性业务环境
                                           ↓ 事件、版本、提交凭据
评估器：隐藏 gold + 日志 ─────────→ 逐轮错误与最终业务评分
```

**业务环境与用户模拟器独立。** 前者确定性保存事实、验证工具前提并产生凭据；后者根据已看到的提问回答、改口、离题或退出，不能直接修改业务终态。优先用可分支脚本稳定诊断，再加入 LLM 用户检验措辞与互动变化。

任务包分四个边界：actor 可见的任务合同/问卷；可检索知识；用户私有事实与行为策略；只给评估器的参考答案及成功条件。问卷 JSON 中只有部署时合法可知的内容，不混入用户私有答案或隐藏场景解答。考核答案如属于合法教师材料，也应由模式规则限制向受测者泄露。

“换 JSON”限于共享 schema 和通用操作能表达的问卷。新领域若需要新的业务操作，应单独增加适配器并在所有组共享，不能偷偷修改某一组的调度或 prompt 后仍称零改动迁移。`questionnaire=null` 可表示无需问卷的任务。

共同环境负责权限、合法提交前提、真实表单/业务字段及其依赖校验、原子状态更新；所有组可用同一接口查询。S 额外增加的是 agent 自动维护的跨任务未决需求、依据、变更关系和行动状态，不是独占真实业务数据库。它的提取/投影也会犯错，须单独评分。候选完成核验只能使用 actor 也能取得的业务凭据和公开合同，不可读取评估 gold。

最低日志字段：conversation/turn/need/field/tool_call/business_operation ID、state revision、模型实际可见信息、字段修改及来源、工具参数和结果、提交前后状态、完成声明、投递状态、pending/failed/cancelled/duplicate/stale-result、结束原因、各角色调用/token 与时间。

## 6. 首轮对照：先诊断，再决定是否扩展

所有组共享模型版本、量化、温度、知识与工具、任务合同、上下文上限、调用/token 上限、用户配置及环境前提规则。同一 case 使用相同初始事实与随机条件配对；互动会导致后续对话不同，不宣称逐字相同。所有评分盲化组名。

| 组 | 唯一计划改变 | 要回答的问题 |
|---|---|---|
| B：适配后的 agent-led / ReAct 风格参考 | 自由选择工具，现有自由笔记；增加所有组共享的正常多轮对话接口 | 当前策略在任务环境中到底在哪一步失败？ |
| P：仅提示 | B + 明确提醒保留多个要求、更新更正、依据凭据判断完成 | 简单 prompt 是否已经足够？ |
| S：持久状态 | P + 逐需求/字段状态、依据与版本维护 | 相对 P，运行时状态管理是否有额外收益？ |
| V：完成核验 | P + 声称完成前读取/核对实际业务凭据 | 相对 P，完成检查是否减少虚报且没有造成过多阻塞？ |
| SV：组合 | P + S + V | 两种机制是否互补，是否增加成本或干扰？ |

主分析以 **P/S/V/SV 的 2×2** 为准：S−P、V−P 是另一因素关闭时的简单效应；平均效应分别为 [(S−P)+(SV−V)]/2、[(V−P)+(SV−S)]/2，交互为 SV−S−V+P。P−B 衡量提示作用。这里估计的是包含计算开销的干预包效果，不把更多模型计算误称为纯表示收益。若 S 有收益，再加同更新频率、同模型、相同 token 上限的自由文本摘要对照；若 V 依赖额外审阅，再加等预算普通复核对照。不能一次加入预算修复、状态、模型升级和异步后只归因于状态。

S 的实现先采用 LLM 从已见信息提取 + 确定性保存/版本规则，不训练新模型。所有读取完整历史的 reviewer/evidence checker 都需清点；否则“actor 遗忘”的差异可能被旁路读完整上下文掩盖。公平比较保持这些旁路一致，并单独报告。

V 覆盖所有用户可见出口：普通回复、卡片/通知、业务回执的自然语言包装；冻结触发规则并核查检测漏检/误检，不能保留绕过审阅的直接发布路径。完成检查要分别记录**尝试发出的错误声明、实际送达的错误声明、正确声明被拦截**及拦截后恢复机会。否则硬性拦截可机械降低虚报率，却掩盖推理没有改善或任务根本没完成。

## 7. 可负担的分阶段规模

以下是排期与成本估算用的规模，不是已完成样本或统计功效承诺。

1. **环境验收**：人工走通两领域各一条成功、一条失败/退出分支；检查修改、保存失败与回执。属于工程测试，不能计入研究成功率。
2. **问题发现**：6 个任务家族（两领域各 3）×4 个条件＝24 个 development case。条件为干净参考、隐含/复合要求、离题后更正、工具失败/延迟。每个家族固定主扰动，其余因素不变；发现失败后用额外最小对照拆开混合因素。任务集须包含纯知识辅导、拒绝可选考核、辅导转考核及暂停分支。一个模型、B 组、每 case 两次，共 **48 次**。先审计这些失败，再决定 S/V 是否值得实现。
3. **开发比较**：同 24 case ×5 组×2 模型×2 次＝**480 次完整设计上限**，包含上述 48 次（只有代码、模型、任务、预算和模拟器完全冻结一致时才复用）。不必一次提交全部运行；先完成一个模型，再复制第二模型，每个模型内部平衡交错各组并记录批次差异。若无相应失败，记录负面结果，停止该机制分支；缺少条件时不再估计完整 2×2 交互。
4. **冻结后的迁移**：另写 12 个新任务家族×2 条件＝24 个未用于调参的 case；P 与预先选定、两模型共用的一个候选组×2 模型×2 次＝**192 次**。冻结代码、prompt、状态 schema、预算、评分及候选选择规则；接口验收不使用测试题调参。至少包含新问卷和新资料；一部分来自第三个非临床领域以测试跨域。任何家族的改写、题目近重复和变体必须在同一 split。测试后不再据此挑选胜者。

如果没有第三领域适配器或专家金标，只能报告新问卷/同领域迁移，不称跨域通用。模型可沿用本地 Qwen2.5 14B 与 Qwen3.5 9B，但开跑前记录精确 tag/digest、量化、上下文、采样、硬件和配置。先测少量代表性轨迹的墙钟与 token 成本，再决定是否负担完整批次；本文没有预估机器时长。

若发现阶段可复用，开发新增 432 次，发现/开发/迁移合计上限 672 次；否则合计 720 次。工程验收、oracle 分支、模拟器核查及额外消融不包含在这些数内。

开发集只有 6 个任务家族/聚类单位，人为设计并未保证抽样独立，重复次数也不等于独立样本。开发结果用于发现机制，不做总体优越性声明。正式样本量应由 pilot 失败率、预定最小有价值改进和任务间方差决定；192 次是可行性迁移检查的计划规模，仍可能不足。

## 8. 归因诊断：oracle 是探针，不是产品

对失败前同一 checkpoint 分支：原始上下文、等长度原文提醒、oracle 当前有效需求/字段（只含已揭示信息）、仅依据当时合法可见信息的下一行动提示。冻结分叉选择规则，完整复制 actor、业务数据库、用户模拟器历史/内部状态、随机数状态、pending jobs、事件时钟、幂等账本与剩余预算。分别记录哪个干预改变了下游结果；不能只给失败组更多剩余预算。先核对实际 model request、checkpoint、工具返回和显示输出，无法归因的保留 unknown/mixed；响应序列化缺失 tool_calls 不能单独证明没有执行。

oracle 有效不证明原失败只由记忆导致；提示可能同时帮助规划。oracle 无效也不证明模型没有理解。结构 S 在普通运行中必须自行从对话获得状态，不能使用 oracle。既有 oracle_trial 属于一次性上下文补充，不等于持续状态机制；新实验复用前应修复旧适配器 context-overflow 重试重复插入补充的风险，并另存新版本。

## 9. 成功、错误、成本如何计分

| 指标 | 分子/分母或判定 |
|---|---|
| 业务目标完整成功率（主指标） | 分母固定为运行前划入“可执行、预期完成”层的全部分配轨迹；所有当前有效要求达成、必要流程约束满足、终态及交付正确、无重大额外错误才成功。agent 导致的挫败退出仍计未完成，不按事后授权状态排除；不以平均字段正确率代替 |
| 合法结局符合率 | 全部 episode 中，完成/暂停/拒绝/退出/待信息等终态是否符合场景条件；同时列出各结局频数，避免靠大量暂停抬高成功 |
| 逐需求/字段正确率 | 当前应完成的有效 requirement/field 中正确处理的比例；同时报告全任务成功与辅导标记 |
| H1–H4 | 分别报告发生该错误的 episode 比例及有定义分母的事件比例；多标签允许共存，区分修复前后，不强迫互斥归因。H3 分开报告错误动作尝试和实际错误状态变化 |
| 跨轮保持与修订 | 先前正确记录的仍有效内容是否保留；更正是否传播到相关字段；过期状态持续多少轮/多久 |
| 失败恢复 | 可恢复工具失败中成功恢复的比例；不可恢复失败是否如实说明；无效重试、重复提交另计 |
| 用户负担/互动 | 不必要的重复追问、离题后恢复所需轮数、泄露考核答案、忽视退出；自然度另做盲化人工评分，不能从业务成功推断 |
| 效率 | actor、审阅/更新器、user simulator 各自调用及 token；真实完成时间、首个有用响应、用户等待、p50/p95；虚拟时钟单列 |

按 case 配对报告百分点差和任务家族聚类的不确定区间；小家族数下强调不稳定，列出每家族结果。token 开销包含失败、重试和被拦截回答。异步超时 episode 不能从分母删除；完成时间需与超时率共同报告。运行前分开“预期完成”和“预设退出/拒绝”等场景；按实际授权持续状态统计仅作描述性补充。agent 自行把难题宣布“待信息”不自动移出主指标。

事件分母预定义为：H1 的已揭示需求/必要澄清机会（识别证据不足另列）；H2 的当前有效状态项在要求更新轮次的保持/修订机会；H3 的实际动作尝试；H4 的用户可见完成声明。零完成声明不等于完成质量高，须与业务成功率并看。未行动造成的漏办保留行为遗漏标签，不硬归入 H3。员工答案及评分是否正确须由独立 rubric 判定；记录保存成功不能证明评分正确。

业务状态和确定性约束先评分，语义解释/自然度再人工或盲化模型辅助评分。LLM judge 不决定数据库是否提交成功。抽查所有虚报完成、全部组间结局不一致与一定比例成功案例；公布分歧和裁决。不能让同一模拟用户随意生成事实又自己判定成功。

## 10. 异步应作为独立的第二实验

先说明 treatment：本研究优先比较**阻塞等待工具**与**工具 pending 时继续处理独立用户信息/任务**，两个条件都只允许一个 actor LLM 调用在途。并行多个 LLM、同时说话或 full-duplex 是另一个因素，不混入这一比较。给工具加 `async def` 本身不是实验。

冻结工具和事件的联合生成规则：相同输入及业务状态产生相同结果，延迟与外部事件用同一随机条件配对；不能要求不同参数也返回相同结果。固定查询读取调用时还是返回时状态、同时事件的排序，以及相同任务依赖和预算。先在确定性时间轴比较：资格查询未返回时是否可回答独立问题；用户更正后旧结果是否作废；用户退出后是否取消；失败重试是否重复提交。外部事件按预声明的相对时间或可观测触发生成，不能为每个组临时改脚本。

资格未确认或用户未接受时，任何组都不能提交。异步可能带来更快首响，也可能带来过期结果、竞争和重复操作。共同正确性约束下比较完整成功、错误、延迟和 token 的权衡，不预设异步更优。

第一步只证明调度语义；第二步才在相同模型/硬件、预热与队列条件下测真实墙钟，交错随机运行顺序并报告后端负载。现有 250 ms 虚拟模型延迟和 pending 检索不能证明真实异步效率。

## 11. 模拟器与迁移的可信度

每条用户 profile 冻结事实、知识水平、披露时机、允许行为及随机条件。单独检查模拟器是否提前给答案、无视拒绝或替 agent 完成工具动作。报告包括这些轨迹的全量结果，以及预声明规则下的有效模拟器敏感性分析；不按哪组获胜选择性剔除。

开发用可分支脚本，之后换独立的用户生成方式/模型，再做少量真人锚点。已有研究发现模拟用户和人类行为存在差距 [S8]；本项目必须直接检验这种风险。复用人类对话片段不能消除其后的模拟偏差。

模型 × harness 交互应报告：某组只改善一个弱模型，结论就限定于该模型；若提升只在已调参问卷上出现，则不支持迁移。相同 LLM 换 harness 有差异并不证明所有失败来自 harness；换模型也不能独立证明架构无需改变。

## 12. 什么结果支持下一步

- 未观察到 S/V 相对 P 有值得额外成本的改善：先保留简单提示，不主张结构贡献；小样本未检出差异不等于证明等效。
- S 改善 H2，但 oracle 状态的收益远大于自动状态：优先研究状态更新质量，而不是扩大 planner。
- V 降低送达虚报但尝试虚报不变、完成率下降：它改善输出约束，尚未证明决策改善；检查误拦截与恢复。
- 正确状态持续可见仍大量 H3：再比较调度/行动策略或工具契约，不继续堆记忆。
- SV 只有加大调用量才有效：报告成本收益，并做等预算摘要/复核对照。
- 异步只改善首响却增加过期提交：不能称总体更好，寻找工作负载边界。
- 所有组接近满分：任务可能过易；在 development 集核查真实来源和扰动，不事后修改冻结测试金标。

推荐执行顺序：先完成 24 个开发 case 的来源与金标审核、共享交互环境，再跑 48 次 baseline。根据真实失败决定干预。当前不需要训练大模型，也不需要先推翻 ReAct。

## 13. 与已有工作如何区分

[ReAct][S5] 本就允许维护与更新计划，不能把它定义成“只能有一个意图”。[τ²-bench][S6] 已将用户任务、政策、工具和终态验证结合；应复用其分层，避免把普通任务型对话包装成空白领域。官方仓库目前已演进至 τ³，任务和 grader 发生过变化；引用原论文和复现当前代码须分别固定版本。

[Gaia2/ARE][S7] 已有动态事件与异步环境；本研究需找出具体任务中异步收益和竞争错误的条件。[FormBharo][S9] 提供了 LLM 抽取加确定性表单管理的相关方案，但其有限表单与模拟覆盖不能证明任意问卷通用。这里潜在贡献是**人类/专家来源的复合任务、过程与终态并行评分、可定位的结构消融及冻结问卷迁移**；贡献是否成立取决于实验结果。
