# 模型 × harness：新会议场景交叉对照

2026-10-17 · 本地诊断实验 · 网站未更新

这轮结果支持一个更具体的判断：模型识别错误和 harness 交付问题同时存在。增加交付检查能让部分正确答案显示出来，但没有形成稳定的完整帮助。接下来需要处理预算分配和答案更新，而不能把所有漏答都归为“模型没有理解 intention”。

## 做了什么

两个本地模型分别运行两个冻结的 harness 配置，在同样四个新写的会议场景上各重复两次，共 **32 次完整运行尝试**。其中三种场景需要帮助，一种场景所有事项都已解决，正确行为是不再提供知识建议。每段会议有九轮人类发言。

- **原 harness**：`agent-led-recovery`，沿用项目已有的调查、工具和恢复逻辑；模型可以主动调用发布工具。它是本项目冻结的对照配置，不等同于未经修改的官方 Deep Agents。
- **交付检查版**：`agent-led-answer-delivery`，在原配置上增加同模型复核，把普通私有回答转为发布、更新、撤回或不展示的决定。这个改动包含额外上下文和一次模型决策，不只是把文本搬到屏幕。

模型为 Qwen2.5 14B Instruct 和 Qwen3.5 9B，均使用本地 Q4_K_M 版本。每次运行共享 24 次模型调用、120,000 累计已知 token、16,384 上下文和单次 1,200 输出 token 上限；temperature=0、reasoning=False。token 上限是软上限，最后一次调用可以超出。调查、交付复核和框架压缩都计入预算。不同 tokenizer 下，相同 token 上限不表示相同算力。

场景、文档、标准和执行顺序在运行前冻结。工具查询同一套虚构资料，不访问实时网页；模型只能看到已经到达的发言。执行顺序在每个场景／重复内平衡，32 次串行完成，失败不挑选重跑。模型和 harness 本身在这轮没有修改。

## 最终交付结果

“完整帮助”要求截止时当前显示的答案覆盖所有必要结论，有适用证据，没有影响判断的错误，也没有仍然有效显示的过时建议。私有回答、进度文字和重复卡片不算成功。正确回答部分问题仍按必要结论单独计分。

每组有 **6 次需要帮助的运行、14 个必要结论检查**；重复运行没有增加独立场景数。

| 模型 | Harness | 完整帮助 | 正确必要结论 | 提前耗尽预算 |
| --- | --- | ---: | ---: | ---: |
| Qwen2.5 14B | 原 harness | 0/6 | 2/14 | 1/6 |
| Qwen2.5 14B | 交付检查版 | 1/6 | 3/14，另 1 项不确定 | 3/6 |
| Qwen3.5 9B | 原 harness | 0/6 | 0/14 | 0/6 |
| Qwen3.5 9B | 交付检查版 | 0/6 | 8/14 | 6/6 |

原 harness 的主要问题是漏交付；交付检查版又暴露出答案更新和成本问题。9B 的正确必要结论从 0 增到 8，但六次帮助场景全部提前耗尽预算，最终仍没有一次完整成功。14B 的唯一完整成功来自 Merrow 的第一次运行，第二次没有复现。

| 独立场景 | 14B 原配置 | 14B 交付检查 | 9B 原配置 | 9B 交付检查 |
| --- | ---: | ---: | ---: | ---: |
| Aster：人数变化与设备 | 0/2 | 0/2 | 0/2 | 0/2 |
| Merrow：部分取消与剩余问题 | 0/2 | 1/2 | 0/2 | 0/2 |
| Cairn：指标含义与时间计算 | 0/2 | 0/2 | 0/2 | 0/2 |

按完整帮助计算，14B 的 harness 差值为 +1/6，9B 为 0/6；两者之差（9B 差值减 14B 差值）为 −16.7 个百分点。这个描述性差异完全来自一次 Merrow 成功，不能当作稳定交互效应或显著性结果。按正确必要结论看，9B 的提升反而更大，因此也不能概括为“14B 全面更好”。

最终卡片中，14B 交付检查版有 1/6 次运行出现影响判断的错误；9B 交付检查版有 3/6 次，其中另有 3/6 次保留过时建议。错误与过时可以重叠，不能相加当失败总数。14B 原配置最终错误为零不表示更可靠：它只交付了 2/14 个必要结论。

## 是模型原因，还是 harness 原因

另外做了 **16 次独立识别诊断**：每个模型看到相同的八个对话前缀，只回答“谁现在需要什么、哪些事项已经取消或解决”。不检索、不生成事实答案，也不把诊断结果放回主实验。

| 模型 | 识别通过 | 失败 | 不确定 |
| --- | ---: | ---: | ---: |
| Qwen2.5 14B | 7/8 | 1/8 | 0/8 |
| Qwen3.5 9B | 5/8 | 2/8 | 1/8 |

14B 的一次失败是把已确认的标签尺寸可调整事项重新列为开放问题。9B 的两次明确失败是漏掉仍未解决的投影设备问题，以及在翻译任务取消后错误地一并丢掉字体问题。这说明显式提示下也会出现识别错误；八个前缀不足以估计模型的一般可靠性，更不能代表运行中的 agent 每次都这样理解。

实际运行记录则提供了另一类证据：

1. **理解后没有展示。** Merrow 第二次运行中，14B 原配置明确写出翻译需求已取消、字体和二维码问题仍然有效，最终却没有显示卡片。9B 原配置也存在正确私有回答而没有卡片的情况。对每个模型分别比较，原配置与交付版早期的一次私有回答完全相同；交付版随后发布，原配置仍保留为私有文本。这定位了这些具体漏答的交付路径问题。
2. **识别了改口，结果仍然失败。** Aster 第一次运行的四组都明确识别人数从 26 变为 38。之后的失败包含投影设备答案在更新中消失，以及把尚待确认的场地说成已经确认。9B 交付版第一次运行的两张卡在更新期间短暂保留不同范围，但最终都已更新；第二次运行才出现最终仍保留旧范围的卡片。不能把这些结果维护问题统称为“没识别人数变化”。
3. **剩余预算阻止了修订。** Merrow 第二次运行的 9B 交付版最后一次调查回复已读到取消信息，也正确保留了另外两人的问题，但预算随后阻止交付复核。不能写成“它没收到取消”或“没理解取消”。整个 9B 交付组只消费了帮助场景的 39/54 轮发言；未到达模型的后续发言不能计作理解失败。

因此，这轮不能给出“多少百分比怪模型、多少怪 harness”。能够定位的是：有些具体错误发生在需求识别，有些发生在事实回答，还有些发生在发布、维护当前答案或预算管理。独立诊断与实际执行记录需要分别解释。

## 成本与不该帮助的场景

下面成本覆盖每组全部八次会议，包括两次沉默对照。时间是一次会议内所有模型调用的累计实测时间，包含加载；不是用户等到第一张答案卡的延迟，也不是模拟对话时钟。

| 配置 | 实际模型调用 | 累计 tokens | 每次会议平均模型时间 | 其中平均加载时间 |
| --- | ---: | ---: | ---: | ---: |
| Qwen2.5 14B / 原 harness | 107 | 534,112 | 29.8 秒 | 3.4 秒 |
| Qwen2.5 14B / 交付检查版 | 166 | 621,386 | 63.4 秒 | 3.1 秒 |
| Qwen3.5 9B / 原 harness | 100 | 531,802 | 20.4 秒 | 3.2 秒 |
| Qwen3.5 9B / 交付检查版 | 168 | 897,082 | 48.2 秒 | 3.4 秒 |

交付检查使 14B 平均累计模型时间从 29.8 秒增至 63.4 秒，9B 从 20.4 秒增至 48.2 秒。模型加载不能解释主要差距。主实验共 541 次实际调用、2,584,382 tokens；独立识别诊断另有 16 次、7,980 tokens。合计 **557 次、2,592,362 tokens**，均为本地推理，未调用付费 API。

| 配置 | 未提供多余知识建议 | 严格零卡片 | 两次运行的发布／更新事件 |
| --- | ---: | ---: | ---: |
| Qwen2.5 14B / 原 harness | 2/2 | 0/2 | 2 |
| Qwen2.5 14B / 交付检查版 | 2/2 | 0/2 | 12 |
| Qwen3.5 9B / 原 harness | 2/2 | 2/2 | 0 |
| Qwen3.5 9B / 交付检查版 | 2/2 | 0/2 | 18 |

按预先规定的内容标准，忠实复述已完成事项的确认不自动算错误，但仍是冗余显示。四组沉默对照都 2/2 通过；只有 9B 原配置做到 2/2 全程零卡片。这个结果不表示频繁确认不会打扰真实用户，也没有混入前面的完整帮助成功率。

## 下一步

先保留这四组和结果作为固定记录，再分别验证三项改动，不同时堆在一起：

- **选择性复核**：普通状态复述不反复进入交付复核，把调用留给新答案、证据变化或真正的任务修订。比较必要结论、重复显示和成本，不能只看调用减少。
- **维护当前答案**：更新只替换被改口影响的部分，保留仍有效的答案和证据，并处理其他卡片中的过时内容。重点看“新答案对了，但旧答案没清掉”和“改一个问题丢掉另一个答案”。
- **为后续输入留预算**：区分调查与交付开销，观察是否能处理到最后一轮和完成修订。这是下一步要检验的方案，不是已经证明有效的修复。

这些场景已经用于诊断，后续可以做回归检查，但不能再称为未见测试集；新的泛化结论需要另写并提前冻结场景。两模型的家族、训练、参数量和 tokenizer 同时不同，不能把差异单独归因于大小。这轮也是脚本文本回放，不是真实 ASR、现场用户测试或开放网页任务；模型调用在模拟时钟中固定计 250 ms，实测时间单独报告。

## 评分与可追溯记录

两位独立 AI 评审只看到匿名输出、当时实际可用的证据和冻结标准，没有模型或 harness 标签。两人对 **32/32 个主结果、56/56 个必要结论标签**一致；14 个次指标分歧已保留并裁决，其中一条中间表述继续标记不确定。独立识别诊断初始一致率为 14/16 个整体标签、26/28 个必要需求标签，分歧与裁决也保留。这里没有人工评分或用户效用验证，评审一致不代表不存在共同判断偏差。

32 次尝试全部保留，包括一次 `BudgetExceeded` 异常和其余提前结束。审计后有两项仅影响分析工具的修正，都以新文件记录，原文件保留：一条模型 start 回调实际发生在预算拒绝前，离线验证没有进入模型调用，因此计 0 次额外推理；另一个评分验证条件误把“冗余确认更新”当作沉默主指标的否决条件，已按冻结的内容规则纠正。没有改模型输出、实验标准、原评审记录，也没有重跑失败样本。
