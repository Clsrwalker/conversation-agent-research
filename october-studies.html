17 OCT · 48 RUNS

Three harness versions, two models

Objective

Test whether successive changes to the same harness improve complete help, and whether both models benefit.

Procedure

2 models × 3 harness versions × 4 scripted meetings × 2 repeats. Harness A, B and C were rerun in the same batch with the same conversations, source documents and total limits: 24 model calls and 120,000 known tokens per run.

What changed in each version

Three successive versions of the same research harness
VersionChanges
Harness AResearch reference. The model chooses what to investigate and when to publish or update an answer.
Harness BHarness A + a delivery check by the same model. It reviews a candidate answer and chooses to publish it, update or withdraw an existing answer, or leave the display unchanged.
Harness CHarness B + resources reserved for later turns and limits on delivery checks. Adds partial answer edits and feedback when updates fail; removes duplicate old answer snapshots from model requests.

Results

Complete help: all required conclusions correct, displayed and current at the deadline.

Conclusion

Harness C delivered the most complete help for both models: 4/6 runs with Qwen2.5 14B and 3/6 with Qwen3.5 9B. It received all nine turns in 16/16 runs, but could still remove valid answers or leave old advice unchanged. These were previously used development meetings; several changes were tested together.

Earlier comparison: Harness A and B

Objective

Test whether Harness B's added delivery check improves delivered help, and whether the result differs between models.

Procedure

2 models × 2 harness versions × 4 new scripted meetings × 2 repeats. Compare Harness A and B with the same research sources, retrieval tools and resource limits. Run 16 separate request-recognition checks.

Results

Complete help by the deadline. Each score covers six help runs.

Conclusion

Harness B delivered more correct conclusions, but complete help remained limited. With Harness B, Qwen3.5 9B answered 8/14 required conclusions while all six help runs stopped early for budget. Recorded failures included missed requests, unpublished answers and incorrect updates.

03

19 OCT · 192 MODEL OUTPUTS

Request recognition

Objective

Test whether a more complete request-finding instruction reduces omissions without adding needs that the conversation does not support.

Procedure

24 scripted conversations × 2 models × 2 instructions × 2 repeats. Compare the usual instruction with a reminder to cover separate requests and avoid unsupported guesses.

Two independent AI reviewers scored the outputs; a third reviewed disagreements and selected examples. Each model and instruction combination has 56 request opportunities: 28 labelled needs, presented twice.

Conclusion

The coverage reminder reduced omissions for Qwen3.5 9B, with some additional unsupported requests. Qwen2.5 14B had no omissions in either condition, but unsupported requests increased from 2 to 8. The reminder did not produce a consistent improvement across models.

Scoring and data

Conversations contain 1–3 turns and at most two information needs. All content is visible in one request. Only request recognition is scored; search, factual answers and delivery are excluded. The ranges are semantic ambiguity bounds, not statistical confidence intervals.

Study limitations

Scripted conversations, local models and AI scoring. Repeats do not add independent scenarios. No real-meeting, live-speech or human-benefit result. Harness B and C remain experimental; the saved reference version is unchanged.
